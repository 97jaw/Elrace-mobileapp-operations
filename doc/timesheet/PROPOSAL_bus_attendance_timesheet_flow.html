Summary

Labour travel by company bus from the accommodation to the project site. The bus has a face device (our own bus app). Today its records stay in a separate database. This proposal brings those records into the foreman's timesheet in the El Race app:

  • Work starts when the labour scans getting off the bus at the site. Work ends when they scan getting on the bus leaving the site. A scan at the accommodation is travel only.
  • The site is the Odoo project whose coordinates contain the bus location.
  • The foreman sees his team prefilled with bus hours before submitting. Rare cases (came late by own car, left by another vehicle) use the existing 1:1 timesheet camera.
  • No manual hours. If neither the bus nor the camera has a record, the foreman contacts support / IT.
  • Data is real time. Final submission stays in our app, daily, within 5 days (existing Odoo rule).

Who does what

Bus face deviceRecords face scans with time and location. The company driver checks the device works every day.
Bus app (our team)Sends every scan in real time: to Odoo (recommended) or directly to the app. Same labour IDs and foremen as Odoo.
OdooMatches the labour, finds the project from the coordinates, works out site start / end / hours per day.
Foreman (mobile app)Reviews his team, fixes rare cases with the 1:1 camera, adds break / overtime / leave, submits.
1:1 timesheet cameraAlready live. Used only when the bus has no record for that labour (or no out).
Support / ITThe only route when neither the bus nor the camera has the hours. No manual edits by the foreman.
Real-time options: (1) Bus → Odoo → App (recommended: one source of truth, payroll and audit in Odoo), or (2) Bus → App, with the app sending the result to Odoo. Both work with the flows below.

Rules

RuleDecision
Source of hoursBus first. 1:1 camera only for what the bus does not have. Manual hours: not allowed (support / IT only).
Work start / endStart = getting off the bus at the site. End = getting on the bus leaving the site. Accommodation scans are travel only.
Which projectThe Odoo project whose coordinates (radius) contain the bus location at the scan.
Team listThe foreman's team, plus any labour whose bus record is at his site. Permanent team changes use the existing labour transfer feature.
Incomplete hoursNot submitted. Salary depends on it, so it is fixed first by 1:1 camera or support.
Break, overtime, leaveEntered by the foreman in the main timesheet as today.
SubmissionDaily, within 5 days (existing Odoo validation).
Data timingReal time (bus → Odoo → app recommended).

Prerequisites before go-live

  1. Bus parking inside the project radius at every site (decided with operations).
  2. Review the coordinates and radius of every active project in Odoo.
  3. Bus app uses the same labour IDs and foremen as Odoo (confirmed). Face enrolment checked for all active labour.
  4. Real-time integration from the bus app (bus → Odoo recommended).
  5. Bus devices send time and GPS location with every scan, and their clocks are synced.
  6. Driver daily check of the device.

Open points

  • Bus app technical stack and integration method (API push to Odoo or direct to the app).
  • Project radius for bus scans: use the existing project radius, or a separate one for bus parking?
  • Pilot: run in parallel with the current process for a few foremen before switching.
