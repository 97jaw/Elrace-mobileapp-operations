Attendance & Timesheet – Functional Flow and Controls

Mobile check-in / check-out, face verification, timesheet pilot and the switches that control them · Prepared by M Jawad · 6 Nov 2026

Purpose

Two things are moving to Odoo and the new mobile app:

  • Staff attendance: one trusted record per employee per day, built from the gate (BioTime), the mobile app and approved requests, so staff payroll can run from Odoo instead of the BioTime report.
  • Site timesheets: foremen will submit from the new app. Before the old app is switched off, both run side by side, and the new app's entries go to a separate pilot table so payroll is never affected.

Every rule below can be switched on or off from Odoo, without releasing a new app version.

Big picture

Mobile check-in / check-out: who can, and from where

The app asks the server every time the check-in screen opens or comes back to the front, so any change in Odoo applies straight away (no logout or app update). The server checks the same rules again when the button is pressed.

Check (in order)Rule
1. Mobile accessMust be ON for the employee (Mobile App Admin → Employee Configuration). OFF = no mobile attendance at all.
2. Remote employeeIf "Remote Check-in" is ticked: no location rule, no device rule. Check-in from anywhere. Time and face rules still apply. Used for online / remote staff (12 employees set today).
3. Gate (BioTime) staffSwitch "Block mobile for BioTime staff". Currently OFF: staff assigned to a gate device can still use mobile.
4. Location – foremenAlways: must be inside the zone of one of their in-progress projects (radius 100 m).
5. Location – other staffWhen "Staff location check" is ON (currently ON): must be inside the zone of an in-progress project where they are on the staff list. If they are not linked to any project with a location, the app shows "No linked location – contact HR".
6. Face verificationIf switched on for the person's role: a 1:1 face check against their own Odoo profile photo (see below).
One record per day: if the employee already entered through the gate, Check In is closed for the day and only Check Out is offered. Gate staff go in and out during the day, so a mid-day gate exit is not treated as the final check-out. The latest check-out of the day always wins, whether it comes from the gate or the mobile app. A record's check-out time is never moved earlier.

Check-out rules (office hours 08:00 – 17:00)

Leaving early needs an approved Temporary Permission (hours based, a short leave) or a Job Mission (half or full day). The Check Out button always stays visible. The rule is explained in a pop-up when it is pressed.

When the button is pressedWhat happens
Before 16:30Allowed only if there is an approved Temporary Permission that has started. Otherwise a pop-up: "Office hours end at 17:00. Apply for Temporary Permission or Job Mission to leave early." Nothing is recorded.
Job Mission (afternoon / full day)Pop-up: "Job Mission – check-out not required". The system records the job-mission times itself.
16:30 – 17:00Pop-up reminder that office ends at 17:00 and a Temporary Permission is needed for leaving early. The employee can confirm and check out.
After 17:00Normal check-out with a simple "Check out at HH:mm?" confirmation. No limit, so overtime is recorded as is.

Times come from the employee's working schedule in Odoo. 17:00 and 16:30 are the defaults and can be changed from the switches.

Face verification (1:1) for attendance

What it checksThe live face in front of the camera must be the same person as the employee's Odoo profile photo, and must be a real live face (not a photo or a screen).
Same engine as timesheetIt reuses the face model, settings and scoring already used for foreman timesheets. App size does not grow. The timesheet face feature is not changed.

Flow

  1. Employee presses Check In or Check Out. All rules above pass.
  2. Camera opens. The face is checked and captured automatically. A shutter button is there as a backup.
  3. Match: attendance is saved. Success screen shows a green tick, date, time, the profile photo and the location name. Done returns to the home screen.
  4. No match: try again. After 3 failures it stops with "Face not matched – try again or contact HR".
  5. No usable profile photo: blocked, "contact HR". Phone too weak to run the check: blocked, "contact your admin".

The match score and a verified flag are stored on the attendance record for audit.

Who gets it

Two switches, and both must be ON: a master switch (system setting) and a role feature "Attendance: Face verification (1:1)", ticked per role in Role Templates (or added for a single user). This applies to attendance only. Timesheet face rules stay as they are.

Timesheet pilot: running the new app alongside the old one

  1. Old app keeps working as today. Its entries go to the real timesheet table, which labour payroll uses.
  2. Pilot foremen also submit from the new app. Those entries go to a separate pilot table. Same screens, same checks, same messages. Payroll, penalties and costing never see the pilot table.
  3. The same foreman can use both apps on the same day. The "one entry per worker per day" rule is checked inside each table separately, so the two apps do not block each other.
  4. Pilot vs Real report in Odoo (Timesheets → Pilot): for each day, project and worker it shows matching entries, different hours, different start/end times, different leave type, and entries missing on one side. This is how we find difficulties before switching.
  5. Go-live = one switch. Turn the pilot switch OFF and the new app writes straight to the real table. No app update needed. The old app can then be retired.

Who is in the pilot: role feature "Timesheet: Pilot (pilot table)", ticked only for the selected foremen.

Decisions needed

  1. Office staff without a project: they are not on any project staff list, so with the location check ON they see "No linked location". Options: add office / branch locations to check in against, or mark them as Remote.
  2. Early check-out policy: confirm the strict rule (before 16:30 only with an approved TP or Job Mission) and the 16:30–17:00 reminder window.
  3. Face verification: which roles must use it from day one.
  4. Timesheet pilot: names of the pilot foremen and the pilot period (suggested 2–4 weeks).
  5. IT: date for completing the BioTime employee cleanup. HR: fix duplicate employee records in Odoo (same code on two people).
